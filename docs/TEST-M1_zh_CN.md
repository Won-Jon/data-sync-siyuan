## 0. 前置准备

1. **装/更新插件**：思源 → 设置 → 集市 → 已下载 → 「安装本地包」→ 选 `package.zip`（已装会提示"是否使用所选本地包更新"）。
2. **重载一次**：把 better-sync 的开关**关掉再打开**（或重启思源）。改代码不会自动热重载，只有数据变更才热重载。
3. **记下可用配置**（测完要恢复）：
   - 手机端（推荐用它当对端）：URL `http://192.168.100.159:6806`，密钥 `wjl030425`，**手机思源要切到前台**；
   - 或电脑端：URL `http://192.168.100.42:6806`，密钥见 `D:\studyNotes\siyuan\conf\conf.json` 的 `api.token`。
4. **开一个取证窗口**（PowerShell，随时贴）：

```powershell
# 看插件设置（URL/密钥/超时是否真的落盘）
Get-Content D:\studyNotes\siyuan\data\storage\petal\better-sync\menu-config.json

# 看最新一条同步日志
Get-Content (Get-ChildItem D:\studyNotes\siyuan\data\.siyuan\sync\logs | Sort-Object LastWriteTime -Descending | Select-Object -First 1).FullName
```

5. （可选）桌面端按 `Ctrl+Shift+I` 打开开发者工具看插件 Console 输出。
6. 测 TC-14 前建议先关掉「即时同步」「启动时同步」，否则指向坏地址会反复弹失败（无害，只是吵）。

## 1. URL 输入校验（M1-P1）

**统一入口**：设置 → 集市 → 已下载 → better-sync → 齿轮（插件设置）→ 第一项「SiYuan URL」。

| 用例 | 输入 | 预期发生什么 | 判定依据 |
|---|---|---|---|
| **TC-01** 协议名笔误 + 端口前多 `//`（本次事故原样） | `htttp://192.168.100.159://6806` | 输入框下方**立刻**出现灰字：`已自动修正为 http://192.168.100.159:6806（协议名 htttp → http、去掉多余的 //）`；鼠标移出输入框后，**框内文字被自动改写成** `http://192.168.100.159:6806` | 目视 + `menu-config.json` 的 `siyuanUrl` = `http://192.168.100.159:6806` |
| **TC-02** 缺协议 + 缺端口 | `192.168.100.159` | 提示 `已自动修正为 http://192.168.100.159:6806（补上 http://、补上默认端口 6806）` | 同上 |
| **TC-03** 末尾多斜杠 | `http://192.168.100.159:6806/` | 提示 `已自动修正为 http://192.168.100.159:6806（去掉末尾斜杠）` | 同上 |
| **TC-04** https 域名不许多事 | `https://notes.example.com` | **无任何提示**，值保持不变（不会乱补 6806） | 同上 |
| **TC-05** 非法协议 | `ftp://192.168.100.159` | **红字**：`不支持的协议 “ftp”，只支持 http / https`；此时点对话框「确认」→ **坏值不会被保存**，`menu-config.json` 里仍是上一个合法 URL（输入框在对话框重开后也会还原成合法值） | 目视 + 对比 `menu-config.json` |
| **TC-06** 非法端口 | `http://192.168.100.159:99999` | 红字：`端口不合法：“99999”，应为 1-65535` | 目视 |
| **TC-07** 非法主机 | `http://:6806` | 红字：`主机名不合法：“:6806”` | 目视 |
| **TC-08** 清空 | （留空） | 红字：`请填写对端设备的地址`（⚠️ 首轮自测此条未复现：该分支当时静默无提示，已修复；需重载插件后复测） | 目视 |

> TC-05 是这组里最关键的一条：**以前坏地址会被原样存进去，然后每次同步都以超时收场**；现在存不进去。

## 2. 测试连接（M1-P2）

**入口**：插件设置 → 「测试连接」按钮（就在 URL / 密钥下面）。

| 用例 | 输入 | 预期发生什么 |
|---|---|---|
| **TC-09** 正常（手机在前台） | URL `http://192.168.100.159:6806`，密钥 `wjl030425` | 逐行出现 5 个 ✔，每行都带「耗时 · HTTP 码 · code」：<br>`✔ 内核版本 — 0.03s · HTTP 200 · code 0`<br>`✔ 笔记本列表 / API 密钥 — …`<br>`✔ 同步目录 data/.siyuan/sync — …`<br>`✔ 对端设备指纹 — …`<br>`✔ 对端时间 — …`<br>再追加 `· 对端设备指纹：<uuid>` 和 `· 两端时钟偏差：x.xs`，最后一行 `✔ 连接正常（对端内核 3.8.5）`；若**首个**请求 ≥3s 会多一行 `⚠ 首次请求耗时 x.xs：对端可能刚从休眠唤醒，属正常现象。` |
| **TC-10** 密钥错 | 密钥改成 `wrong-key-123` | 第 1 行 ✔（`/api/system/version` 不需要密钥），第 2 行 ✘ `HTTP 401 · code -1 · Auth failed [header: Authorization]`，结论 `✘ 连接失败：API 密钥不正确。请在对端思源「设置 → 关于 → API token」里复制密钥。` |
| **TC-11** 端口错 | URL 改 `http://192.168.100.159:6999` | 第 1 行 ✘（`TypeError: fetch failed`），结论 `连不上对端：地址或端口写错、对端没有开启「网络伺服」，或两台设备不在同一局域网。` |
| **TC-12** 对端休眠（真实高频场景） | 手机锁屏 / 切后台静置约 1 分钟，再点测试 | 卡住约 **15s**（等于当前超时设置）后：第 1 行 ✘ `AbortError: This operation was aborted`，结论 `对端在超时时间内没有响应。若对端是手机/平板，通常是思源被切到后台或系统休眠了——请把它切到前台再试，或把「网络请求超时」调大。`；把手机切回前台再点一次应全绿 |
| **TC-13** 超时设置生效 | 把「网络请求超时（毫秒）」改成 `30000` → 点「**确认**」→ 重复 TC-12 | 这次等待约 **30s**（而不是 15s），其余表现同上；`menu-config.json` 里出现 `"requestTimeoutMs":30000`。<br>注：值在对话框「确认」时生效（确认后会重新初始化同步管理器，不用重载插件） |

## 6. 出问题怎么取证 / 回滚

1. **三件套**：`menu-config.json`（配置是否落盘）、最新 `data/.siyuan/sync/logs/*.log`（现在能看到真实错误+堆栈+重试记录）、开发者工具 Console（`Ctrl+Shift+I`）。
2. **回滚**：把安装目录换回 `D:\studyNotes\siyuan\data\plugins\better-sync.bak-20260923-164411`，或从集市重新安装 v1.5.2。
3. **注意**：TC-14 会把插件指向不可达地址，测完务必恢复；否则开着的「即时同步/启动时同步」会一直报失败（数据无风险，仅噪音）。
