2. **重载一次**：better-sync 开关**关掉再打开**（或重启思源）。
3. **记录可用配置**（测完恢复）：URL `http://192.168.100.168:6806`（手机当前 IP，若变了用「测试连接」确认）、密钥、`requestTimeoutMs`。
4. **取证窗口**（PowerShell）：

```powershell
# 设置是否落盘
Get-Content D:\studyNotes\siyuan\data\storage\petal\better-sync\menu-config.json
# 最新一次同步日志（失败排查、并发观察都看它）
Get-Content (Get-ChildItem D:\studyNotes\siyuan\data\.siyuan\sync\logs | Sort-Object LastWriteTime -Descending | Select-Object -First 1).FullName
```

5. 建议先把「即时同步」「启动时同步」关掉，避免测试期间被后台同步干扰。

## 1. 进度面板（M2-P1 / M2-P3）

| 用例 | 你做什么 | 会发生什么 |
|---|---|---|
| **TC-M2-01** 面板出现与阶段推进 | ① 设置里把「并发请求数上限」改成 `1`（放大可观察性）→ 确认 ② 点顶栏云图标同步 | 右下角出现半透明面板（不可点击、不挡操作），标题按阶段变化：`同步中 · 准备` → `同步中 · 扫描文件` → `同步中 · 传输文件` → `同步中 · 收尾处理`；第二行显示 `目录 i/N · 文件 i/M`（i 单调递增、i ≤ N）；第三行显示当前正在传的文件路径；进度条随"文件 i/M"增长 |
| **TC-M2-02** 完成态自动收起 | 同步正常结束 | 标题变 `同步完成`，进度条到 100%，约 **4 秒**后面板自动消失；顶栏图标照旧变回成功图标 |

## 2. 并发限流（M2-P2）

| 用例 | 你做什么 | 会发生什么 |
|---|---|---|
| **TC-M2-05** 设置落盘 | 设置里「并发请求数上限」改成 `4` → 点「确认」 | `menu-config.json` 里出现 `"maxConcurrentRequests":4` |
| **TC-M2-06** 串行（上限=1） | 设为 `1` → 确认 → 同步一个改动较多的目录 | 面板的 `文件 i/M` 是**一个一个**跳；日志里 `Executing sync operation:` 与 `File … synced successfully.` 基本严格交替，**不会**出现一长串 `Executing` 挨在一起 |
| **TC-M2-07** 并行（上限=16） | 设为 `16` → 确认 → 再同步同样内容 | 日志里能看到多条 `Executing sync operation:` **连续成串**出现（同时有多个文件在传），整体耗时通常更短 |
| **TC-M2-08** 边界值（运行时夹取） | 依次填 `0`、`-5`、`999` 并确认 | 输入值**原样存盘**（不擅自改写你的输入），但运行时被夹取：`0`/负数 → 按默认 8 跑；`>64` → 按 64 跑。判定方式：用上面的"串行/并行"观察法对比日志密度 |
| **TC-M2-09** 手机对端不再成片超时（回归，建议做） | 用手机当对端 + 并发 `8`（或 `4`）→ 触发一次较大范围的同步 | 日志里**不应**再出现成批的 `Request timeout for …`；偶发单条超时会自动重试（日志里有 `attempt 1/3`） |

> 这一条是 M2 的核心收益：以前"每个文件/每个目录一次性全发出去"，手机端很容易被压垮。

## 3. 测试连接新增内容（M2-P4 / M2-P5）

| 用例 | 你做什么 | 会发生什么 |
|---|---|---|
| **TC-M2-10** 对端数据仓库状态 | 点「测试连接」（对端=手机或电脑） | 步骤列表里多出一行 `✔/✘ 数据仓库（快照） — x.xxs · HTTP 200 · code 0 或 -1 …`：<br>• 已初始化 → `✔`，并在下面追加 `· 对端数据仓库已初始化（N 个快照）`<br>• **未初始化** → `✘` 且 detail 是对端原文（"请先…初始化数据仓库密钥"），并追加一行 `⚠ 对端数据仓库未初始化：同步前快照不可用。如需快照，请在对端「设置 → 账号与同步 → 本地数据仓库」初始化数据仓库密钥。`<br>注意：这一步**不会**把整个测试判为失败（快照是可选功能） |
| **TC-M2-11** 本机区块 | 同一次「测试连接」，看报告末尾 | 出现「本机」小节：`· 本机内核：3.8.5`、`· 本机 API 密钥来源：设置页（运行中的内核，权威值）`、`✔ 本机 API 密钥自测：通过`（若来源是 `conf/conf.json` 且自测失败，会给出"请以设置页显示值为准"的提示） |

> M2-P5 的结论（已实测查清）：`conf/conf.json` 里的 API token **可能滞后于运行中的内核** —— 首次排查时该文件里的值被内核以 `401 Auth failed` 拒绝；随后你在界面/文件里把它改成 `wjl030425` 后同一接口立刻 200。所以插件现在**优先读运行中内核的值（设置页来源）**，并且**每次都自测一遍**；`conf.json` 只作兜底。这条直接决定 M3「二维码」印出来的密钥是否可用。

## 4. 快照引导（M2-P4）

| 用例 | 你做什么 | 会发生什么 |

| **TC-M2-12** 未初始化仓库时的提示 | ① 打开「创建数据快照」② 对端数据仓库未初始化（TC-M2-10 已确认）③ 同步一次 | 弹出提示（约 **10 秒**）：`{{对端名}} 的数据仓库未初始化，已跳过同步前快照。如需保护：请先在两端「设置 → 账号与同步 → 本地数据仓库」初始化数据仓库密钥，再开启「创建数据快照」。`；**同步本身照常继续**（快照是可选步骤） |

| **TC-M2-14** 两边都初始化后（可选） | 在两端「设置 → 账号与同步 → 本地数据仓库」初始化密钥 → 再同步 | 不再出现"未初始化"提示；对端会出现一条 `[better-sync] Cloud sync` 快照（在思源的「数据历史/快照」里能看到） |

## 6. 出问题怎么取证 / 回滚

1. **三件套**：`menu-config.json`（配置是否落盘）、最新 `data/.siyuan/sync/logs/*.log`（含重试、并发顺序、真实错误+堆栈）、开发者工具 Console（`Ctrl+Shift+I`，插件 consoleLog 都在这里）。
2. **进度面板不出现** → 先确认插件已重载；再看 Console 是否有 `Progress callback failed`（面板渲染异常会被捕获并打日志）。
3. **回滚**：换回 `D:\studyNotes\siyuan\data\plugins\better-sync.bak-20260923-164411`，或用「安装本地包」重装集市版 v1.5.2。
4. TC-M2-03 会把插件指向不可达地址，**测完务必恢复** URL。
