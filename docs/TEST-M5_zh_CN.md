> 包：`D:\siyuan-plugins\data-sync-siyuan\release\package.zip`（SHA256 `A5659D55053EC2BDE78F7BF44F467C65F22FE6AA953ECBE9F4C5FD717AE4F617`）
> 前置：装包 → **重载插件**（关掉开关再打开）
> 入口：插件设置 → **「选择性同步（自选笔记本 / 目录 / 排除规则）」**
> 配置文件：`data\storage\petal\better-sync\sync-config.json`（可直接看/改，保存后**下次同步生效**，不需要重载插件）
> **总原则（M5-P7）**：取消勾选 = **停止比对与传输**，**绝不删除任何一边的数据**。

## 1. 默认与基础行为

| 用例 | 你做什么 | 会发生什么 |
|---|---|---|
| **TC-M5-01** 默认全选（升级不改变行为） | 装完不碰「选择性同步」，直接同步 | 一切都同步（与升级前完全一致）<br>**判定**：`sync-config.json` 不存在，或内容为 `{"version":1,"notebooks":{"mode":"exclude","ids":[]},"dirs":{"mode":"exclude","paths":[]},"rules":[]}` —— 即"排除为空＝全选" |
| **TC-M5-02** 取消勾选一个笔记本 → **不删除数据** | ① 设置里**取消勾选**笔记本 B → 点「保存」② 在电脑上把 B 里某个文档改成很显眼的内容 ③ 同步 | ① B 的改动**不会**传到手机 ② **手机上 B 的内容依然在**（只是不参与比对/传输，不是删除）③ 日志里这次会话的目标数比全选时少（少了 `data/B` 与其 `.siyuan` 两个目标） |
| **TC-M5-03** 只勾一个笔记本（include 模式） | 只勾选 A → 保存 → 同步 | `sync-config.json` 变成 `"notebooks":{"mode":"include","ids":["<A的id>"]}`；只有 A 被比对；其它笔记本原样不动 |
| **TC-M5-04** 目录勾选 | 取消勾选 `data/plugins` → 保存 → 同步 | 插件目录不再被比对/传输（**不会**删掉对端的 plugins 目录）。恢复勾选即恢复同步 |
| **TC-M5-05** 全选 / 全不选按钮 | 点「全不选」→ 保存（先别同步，可先看配置） | `notebooks` 与 `dirs` 都变成 `{"mode":"include","ids":[]}` / `{"mode":"include","paths":[]}` —— 两个列表是**各自独立**的：笔记本空 = 笔记本全不同步，目录空 = 目录全不同步；**依然不会删除任何数据** |

## 2. 通配排除（M5-P3，旧版只支持精确文件名）

| 用例 | 你做什么 | 会发生什么 |
|---|---|---|
| **TC-M5-06** 扩展名通配 | 规则行填 `data/assets: *.psd, *.zip` → 保存 → 在 `data/assets` 放 `a.psd` 和 `b.png` → 同步 | `a.psd` **不传输**；`b.png` **正常传输**（旧版 `excludedItems.includes(name)` 做不到这点） |
| **TC-M5-07** 规则继承到子目录 | 规则 `data/assets: *.psd` → 在 `data/assets/sub/x.psd` → 同步 | 同样不传输（规则对子目录生效） |
| **TC-M5-08** 前缀通配（不是"任意路径"） | 规则 `2026xxxx-xxxxxxx: draft*`（填你某个笔记本的真实 id）→ 该笔记本下建 `draft-1.sy` 与 `note.sy` → 同步 | `draft-1.sy` 不同步；`note.sy` 正常同步（`*` 只匹配一段名字，不跨 `/`；跨层要用 `**`） |
| **TC-M5-09** 问号与特殊字符 | 规则里用 `a?.md`；文件名 `a1.md` 与 `a12.md` | `a1.md` 被排除，`a12.md` 不受影响（`?` 恰好一个字符）；`+` `.` 等正则元字符按字面匹配 |

## 3.5 嵌套子文档（父文档 / 子文档）怎么选？（2026-09-24 提问后补充）

**先明确粒度**：M5 的选择粒度是「笔记本 / 目录 / 按目录的名字规则」，**没有"文档树勾选"**。勾选笔记本 = 这个笔记本里的**所有文档、所有层级**都同步。

**真实存储结构**（在你工作区磁盘上实测得到）：
```
data/<笔记本id>/<父文档id>.sy                        ← 父文档本体（一个文件）
data/<笔记本id>/<父文档id>/<子文档id>.sy              ← 子文档（目录名 = 父文档的 id）
data/<笔记本id>/<父文档id>/<子文档id>/<孙文档id>.sy    ← 还能继续嵌套（实测到四层）
```
关键：**父文档本体是 `<父id>.sy` 文件，子文档放在同名目录 `<父id>/` 里** —— 同名但不同物，这决定了排除规则怎么写。

| 用例 | 你做什么 | 会发生什么 |
|---|---|---|
| **TC-M5-14** 勾笔记本 → 子孙全同步 | 只勾该笔记本（或默认全选） | **所有层级**的子文档都在范围内（父/子/孙/曾孙四级实测通过） |
| **TC-M5-15** 只排除父文档本体、保留子文档 | 规则 `data/<笔记本id>: <父文档id>.sy` | 父文档本体不同步；**子/孙/曾孙照常同步**（`.sy` 文件与同名目录是两回事） |
| **TC-M5-16** 父文档 + 全部子孙一起排除（一条规则） | 规则 `data/<笔记本id>: <父文档id>*` | 父本体 + 整棵子树全部不参与同步；**同层兄弟文档不受影响** |
| **TC-M5-17** 只排除某个子文档 | 规则 `data/<笔记本id>/<父文档id>: <子文档id>.sy` | 该子文档本体不同步；**它自己的子文档仍会同步**；要连子孙一起排除就写 `<子文档id>*` |

**本版做不到的**：不能"只选某几篇文档"。include 模式只作用于**笔记本 / 目录**级；在 `dirs` 里写 `data/<nb>/<父id>` **不会**把笔记本拆到子目录级（该路径不是同步目标）。想要"文档级勾选"（树形勾选 + 勾父带子）需要新增功能，确认后即可做。

> ⚠️ **必须用本轮新包**：这些嵌套场景是用你工作区的真实 id 与真实路径跑的回归，**抓到一个真 bug**（规则挂在笔记本根路径上时被跳过 → 父文档本体排不掉），已修复；旧包存在该问题。

## 6. 已知限制

1. **`data/storage/petal/better-sync` 永远不同步**（插件自身设置，含对端 URL 与密钥）—— 这是原有行为，不是选择性同步的反例。
2. **两个列表独立**：笔记本勾选与目录勾选互不影响；"全不选"会同时清空两边。
3. **规则按目录挂**（`目录: 通配`），不支持跨目录的全局通配（要排除所有目录里的 `*.psd`，需为每个目录各写一行）。
4. **生效方是"发起同步的那台"**：结合 M4 的方向所有权，实际就是"所有者那台的勾选说了算"。
5. 手工改 `sync-config.json` 后**不必重载插件**，下次同步即读取；但界面上的勾选状态要重新打开设置才会刷新。
