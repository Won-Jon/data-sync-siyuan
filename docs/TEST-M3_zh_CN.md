# M3 手工测试用例：二维码配对 / 扫码接入 / 一键连接

> 包：`D:\siyuan-plugins\data-sync-siyuan\release\package.zip`（SHA256 `D5BFAB75F3D9DF8AAF4E99D98892026D410B5CF7B460FD0D362FB66B1FB2A423`）
> 前置：装包（安装本地包）→ **把插件开关关掉再打开**（必须重载，新依赖才会生效）
> 入口：插件设置里新增三块 —— **生成连接二维码** / **扫码 · 粘贴接入** / **已配对设备（一键连接）**
> 建议姿势：在**常年开机的那台**上生成二维码，在**另一台**上扫码接入（这样断线重连时总是能找到人）

## 1. 生成侧（被连接的一方）

| 用例 | 你做什么 | 会发生什么 |
|---|---|---|
| **TC-M3-01** 生成二维码 | 电脑端 → 插件设置 → 点「生成连接二维码」 | ① 状态先显示「正在读取本机地址与密钥并自测…」<br>② 白框里出现**完整的黑白二维码**（**不是空白白框** —— M3.1 修过这个 bug，见文末）<br>③ 上方列出地址自测结果，每行形如 `✔ http://192.168.100.42:6806 — 0.05s`<br>④ 出现「复制连接文本」按钮<br>**判定**：清单里应出现 `http://<你的局域网IP>:6806`（**6806 排在前面**；50179 那种随机 UI 端口只作兜底排在后面）；不应出现 `127.0.0.1` |
| **TC-M3-02** 复制连接文本 | 点「复制连接文本」 | 提示「已复制到剪贴板。」；文本形如 `bsync:v1:{"u":["http://192.168.100.42:6806"],"k":"<你的 token>"}`（可粘到记事本核对） |
| **TC-M3-03** 二维码可被识别（只能人工确认） | 用手机系统相机 / 微信扫这个二维码 | 扫码结果里能看到上面那段 `bsync:v1:{...}` 文本（说明码是有效的、不是花屏） |
| **TC-M3-04** 密钥不对时不给出坏码 | 临时把本机 API token 改成错误的（`设置 → 关于 → API token` 改完记得改回）→ 再点生成 | 不出二维码，提示「本机 API 密钥自测失败（HTTP 401）：请以『设置 → 关于 → API token』显示的值为准。」（**这是刻意设计**：码里绝不会带一个连自己都不认的密钥） |

## 2. 接入侧（扫码 / 粘贴）

| 用例 | 你做什么 | 会发生什么 |
|---|---|---|
| **TC-M3-05** 粘贴接入成功 | 在**另一台设备**的插件设置里，把上面的文本粘到「扫码 / 粘贴接入」→ 点「解析并连接」 | ① 状态「正在尝试 1 个地址…」→「已连接 `http://192.168.100.42:6806`（设备指纹 `xxxxxxx`）」<br>② 上面的 **SiYuan URL / API 密钥被自动填好**（不用手抄）<br>③ 下方自动出现完整**连接诊断报告**（内核版本/密钥/同步目录/设备指纹/数据仓库/时钟 + 本机块）<br>④ 下面「已配对设备」列表立即出现这条记录 |
| **TC-M3-06** 容错解析（手抄错的地址也能救） | 故意贴这些变体：<br>① `http://192.168.100.42` （缺端口）<br>② `htttp://192.168.100.42://6806`（协议名多 t + 多斜杠）<br>③ 两行式：`192.168.100.42:6806` 换行 `你的token` | 三种都应被**自动修正**并成功连接（修正规则就是 M1 那套：协议名/多余斜杠/补默认端口 6806）；若真连不上，会给出**分级原因**（401 密钥 / 超时休眠 / 连不上 / 不是思源内核），而不是一句"失败" |
| **TC-M3-07** 摄像头扫码 | 若平台支持（浏览器有 `BarcodeDetector`）应显示「用摄像头扫码」按钮 → 点它 | 出现摄像头画面并自动识别二维码 → 自动填入并连接。<br>**若平台不支持**：按钮不显示（或提示「此设备不支持内置扫码…请用手机相机扫出文本后粘贴」）—— 这时走 TC-M3-05 的粘贴路径即可 |
| **TC-M3-08** 完全无关的文本 | 贴一段随便的文字 → 点连接 | 提示「这段文本不是 better-sync 的配对文本。」或「配对文本里没有地址 / 没有 API 密钥」——**不会**静默失败 |

## 2.1 手机接入的两条路径（M3.1 补充：思源 App 里没有系统级扫码）

| 用例 | 你做什么 | 会发生什么 |
|---|---|---|
| **TC-M3-14** 手机：系统相机/微信扫码 → 复制 → 从剪贴板读取（**推荐**） | ① 手机用系统相机或微信扫电脑上的二维码 → 会看到一段 `bsync:v1:{…}` 文本 ② 复制它 ③ 打开手机上思源的 better-sync 插件设置 → 点「**从剪贴板读取**」 | 文本被自动读入输入框并**立即开始连接**（等同于点「解析并连接」）：显示「正在尝试 N 个地址…」→「已连接 …（设备指纹 …）」+ 连接诊断报告。<br>若系统未授权剪贴板：提示「读不到剪贴板（系统未授权）：请在下面的输入框里手动长按粘贴」→ 走手动粘贴 |
| **TC-M3-15** 手机：直接粘贴（零依赖兜底） | 把那段文本用微信/飞书发到手机（或在手机上长按复制）→ 在插件设置的输入框里长按粘贴 → 点「解析并连接」 | 同 TC-M3-14 的连接结果。**这条不需要摄像头、不需要剪贴板权限，永远可用** |
| **TC-M3-16** 实时取景扫码（M3.4 起：`getUserMedia` + jsQR 逐帧解码） | 点「用摄像头扫码」→ 对准二维码 | **桌面 / 允许摄像头的平台**：出现取景画面，自动识别 → 自动填入并连接；按钮变「停止扫码」，再点即停（90 秒自动停止）。<br>**思源安卓 App**：会明确提示「本机 App 不允许插件使用摄像头（思源安卓端的 WebView 只放行麦克风）…请用『拍照识别二维码』或用手机相机/微信扫码后『从剪贴板读取』」——这是 **App 的限制**（源码证据见 §5），不是插件故障 |
| **TC-M3-17** 手机：**拍照识别**（推荐，无需任何权限改动） | 点「**拍照识别二维码**」→ 系统相机打开 → 对着电脑屏幕上的二维码拍一张 → 确认 | 提示「正在识别图片中的二维码…」→ 识别成功则自动填入并连接（等同 TC-M3-05）；识别不到时提示「请让二维码在画面里更大一些、对准并避免反光」，可重拍 |
| **TC-M3-18** 手机/桌面：**选图片识别** | 点「选图片识别」→ 从相册选一张二维码截图/照片 | 与 TC-M3-17 相同的识别与连接流程（适合已经截了图的情况） |

> 结论：**二维码不是必需环节**。「复制连接文本 → 发到手机 → 粘贴（或从剪贴板读取）」是最稳的路径；摄像头扫码只是锦上添花。

## 3. 已配对设备（一键连接，免重复扫码）

> 记录文件：`D:\studyNotes\siyuan\data\storage\petal\better-sync\connections.json`（形如
> `[{"fingerprint":"54899d17-…","urls":["http://192.168.100.42:6806"],"token":"…","lastOkAt":1790230000000,"kernelVersion":"3.8.5"}]`）

| 用例 | 你做什么 | 会发生什么 |
|---|---|---|
| **TC-M3-09** 一键连接 | 点记录行上的「连接」 | 状态「正在尝试 N 个地址…」→「已连接 …（设备指纹 …）」+ 自动重跑连接诊断；`lastOkAt` 更新（列表里显示「上次成功：…」） |
| **TC-M3-10** IP 变了也能找回（核心） | 手工把 `connections.json` 里那条的 `urls` 改成 `["http://192.0.2.1:6806","http://192.168.100.42:6806"]`（**黑洞地址在前、正确地址在后**）→ 点「连接」 | 会**先对黑洞地址超时**（约 8s），再自动试第二个地址并**匹配指纹成功** → 连接成功；展开的探测明细能看到 `✘ …timeout` 与 `✔ …match` 两行。这就是"对方换了 IP 也能找回"的机制（靠的是指纹，不是 IP） |
| **TC-M3-11** 认错设备的保护 | 把那条记录的 `fingerprint` 改成别的值（如 `other-device-id`）→ 点「连接」 | **拒绝连接**并提示「这些地址回答的是别的思源设备（IP 可能被其他设备占用了），请重新扫码。」——不会把同步指向一台陌生设备 |
| **TC-M3-12** 密钥已变更 | 把记录里 `token` 改成错的 → 点「连接」 | 提示「对端拒绝了密钥（401）：密钥可能已变更，请重新扫码/粘贴。」；列表里该条显示「上次失败：…」 |
| **TC-M3-13** 置顶 / 删除 | 点「置顶」再点「删除」 | 置顶后该条排到最前（标题带 📌）；删除后消失。这两项都写回 `connections.json` |

## 5. 已知限制

0. **为什么手机上"实时摄像头扫码"按钮时有时无**（2026-09-24 查证）：
   思源 Android App 的源码（`siyuan-note/siyuan-android`，`MainActivity.java`）里，WebView 的 `onPermissionRequest` **只放行麦克风**（`RESOURCE_AUDIO_CAPTURE`），对摄像头（`RESOURCE_VIDEO_CAPTURE`）一律拒绝 → 插件里的 `getUserMedia` 在安卓上必定失败。App 虽然在 manifest 里声明了 CAMERA 权限，但那是给"拍照插入文档"用的原生通道（`onShowFileChooser` → `ACTION_IMAGE_CAPTURE`）。
   **所以插件改用那条原生通道**：`<input type="file" capture>` = 「拍照识别二维码」（TC-M3-17），另外提供「选图片识别」（TC-M3-18）。想真正用 `getUserMedia` 实时预览扫码，只能 fork 并重编译 Android App（约 10 行 Java 放行 video capture），代价是自签名安装 + 每次官方更新都要重新打补丁，**不推荐**。
   **M3.4 补充两点事实**：
   - 「拍照识别」**会在相册留一张照片**：App 的 `openCamera()` 里是 `getContentResolver().insert(MediaStore.Images.Media.EXTERNAL_CONTENT_URI, …)`，把系统相册当输出目标（`MainActivity.java:1266`）。这是 **App 行为**，插件无法删除；插件已在界面加了提示。
   - 插件内的**实时取景扫码已实现**（`getUserMedia` + jsQR 逐帧解码，每 300ms 一帧、降采样到 480px）：**桌面端可直接用**；安卓端会因上面那条 App 限制而失败，并给出明确指引。
   - **零照片、真实时扫码的做法**：用手机自带相机/微信扫（实时取景由它们提供）→ 复制文本 → 插件里点「**从剪贴板读取**」。这条路不需要摄像头权限、不产生照片、不需要改 App。


1. **摄像头扫码依赖浏览器的 `BarcodeDetector`**：桌面 Chrome/Electron 与部分 Android 版本有、部分没有。没有时按钮不显示，请用手机相机扫码 + 粘贴（粘贴路径是主路径，已完整实现）。
2. **二维码里不含昵称**（二维码编码器默认只支持 Latin-1，为避免中文乱码，载荷保持纯 ASCII：地址 + 密钥）。
3. **地址自测只覆盖本机可访问的地址**：如果路由器做了 AP 隔离 / 多网段，本机能通不代表对端能通；此时用「连接诊断」看对端视角，必要时在二维码里手动补地址（`connections.json` 里加候选即可）。
4. 密钥会保存在 `connections.json`（明文，与 `menu-config.json` 同一目录）。若你不希望保存，可手工删掉该字段：删后一键连接只填地址、需要你补密钥。
